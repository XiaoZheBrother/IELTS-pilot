# IELTS Pilot 当前页面上下文助手设计

## 目标

让悬浮助手在阅读练习、阅读复盘、写作草稿和写作报告页面自动理解当前材料。用户无需复制粘贴，即可追问“原文哪一句支持答案”“为什么用这个词”“这段为什么这样写”。

## 产品边界

- 上下文只在用户主动发送消息时交给已配置的 AI，不因打开悬浮球而出站。
- 对话历史只保存用户问题、助手回答和精简证据摘要；不重复保存整篇原文或整篇作文。
- 阅读上下文包含全文、全部题干、当前题完整选项、用户答案、标准答案、解析和原文定位。
- 写作上下文包含任务要求、当前草稿或已提交作文，以及报告中的四项维度、证据与改写建议。
- 内置材料完整发送；超长导入材料在 12,000 字符的 provider 消息上限前有界截断，并在界面明确提示。
- 当前页面材料生成稳定的 `context.*` 证据 ID，AI 的关键判断仍必须经过现有结构化回答校验。

## 交互

- 悬浮球在阅读练习和模考页面保持可用。
- 对话页顶部显示“当前上下文”卡片、材料类型、标题、题目数量、当前题号和是否截断。
- 阅读场景提供“为什么是这个答案”“原文证据在哪”快捷问题；写作场景提供“解释当前表达”“如何改写”快捷问题。
- 输入区旁明确说明：发送消息会同时发送当前页面的学习材料，不包含 API Key。

## 技术方案

1. 新建纯领域模块，把路由、题库、草稿、练习结果和写作报告转换为有界的 `AssistantPageContext`。
2. 将上下文证据合并进 `EvidenceCatalog`，并把 `ActivePageContext` 加入 assistant-v3 payload。
3. 每次打开助手或路由变化时重新读取本地仓库，避免把旧题目误当作当前题。
4. 助手回答持久化时只保存精简证据目录，以便离开页面后仍能查看证据链。
5. 用领域测试覆盖四类页面、长度上限、无上下文页面和证据 ID；用组件测试验证真正出站的 provider payload。
