# 批量内容包导入设计

## 目标

让题库包管理页一次选择多个 JSON 内容包，完成批量校验、统一预览和一次确认安装。单个无效包或冲突包不得阻断其他可安装包，现有单包导入、来源确认、版本检查和冲突保护保持不变。

## 用户流程

1. 文件选择框允许一次选择一个或多个 `.json` 文件。
2. 应用按用户选择顺序读取并校验全部文件。
3. 页面展示批量摘要，分别列出可安装、可升级和不可安装的内容包；格式错误也显示对应文件名和原因。
4. 用户点击一次“安装全部可用内容包”，应用只安装通过校验且无冲突的包。
5. 安装完成后显示安装数、跳过数和失败原因；已安装内容包列表立即刷新。

选择单个文件时沿用同一批量模型，但页面仍展示完整的单包预览信息，以保持当前使用体验。

## 状态与组件边界

`PackageManagerView` 将单一 `incoming` / `preview` 状态替换为批次条目列表。每个条目包含文件名、解析后的内容包、预览结果和错误信息，状态仅允许以下三类：

- `ready`：新安装或合法升级，可以进入批量安装。
- `blocked`：格式有效，但因最低版本、包版本或练习 ID 冲突而不可安装。
- `invalid`：文件读取失败、JSON 无效或内容包字段校验失败。

批次派生出可安装数量、跳过数量和总练习数。单包详细预览继续复用 `PackagePreview`；批量时为每个有效包展示精简状态行，避免同时渲染大量完整预览。

## 数据流与原子性

文件读取阶段并行读取文本，但按文件选择顺序生成结果，保证反馈稳定。预览检查必须按“假设前一个可用包已经安装”的顺序执行，这样同一批次内重复的 `packageId`、版本倒退和练习 ID 冲突会在确认前被识别。

确认安装时，应用按预览顺序依次调用现有 `installPackage`。每次成功后将返回的安装包集合用于下一次安装，最后只调用一次仓储写入，避免产生中间页面状态。若确认期间出现意外失败，失败项被记录并跳过，其他已验证条目继续处理；最终一次性持久化全部成功结果。

## 错误与安全边界

- 不执行内容包脚本，继续使用现有 `validateContentPackage`。
- 不因一个坏文件清空整个批次，也不隐藏具体文件名。
- `conversion-report.json` 等非内容包 JSON 会明确标记为无效并跳过。
- 批量按钮仅在至少一个条目为 `ready` 时启用。
- 用户重新选择文件会替换当前待安装批次，避免重复确认旧批次。
- 安装前仍显示来源、许可和备注；批量确认文案明确表示只安装可用项。

## 测试与验收

单元测试覆盖：

- 文件输入支持 `multiple`。
- 两个有效包可在一次确认后同时安装。
- 有效包与无效 JSON 混选时，有效包仍可安装并显示跳过原因。
- 同一批次内的练习 ID 冲突在预览阶段阻止后一个包。
- 单包预览与卸载行为不回归。

Playwright 使用本地生成的 11 个 `private-atlas-*.json` 一次性调用 `setInputFiles`，点击一次批量安装按钮，验证 11 个内容包全部出现，并在题库页找到 P1 与 P3 代表文章。最终运行类型检查、全部单元测试、生产构建、集成测试和目标 E2E。

## 非目标

- 不导入文件夹、ZIP 或远程 URL。
- 不自动确认第三方许可。
- 不绕过版本、来源、字段或练习 ID 冲突检查。
- 不在本次改动中迁移浏览器存储实现。
