# IELTS Pilot v0.6-v0.8 安全发布、同步与内容源设计

## 目标

在不破坏“本地优先、无默认账号、无遥测”的前提下，按路线图顺序完成三个可独立交付的里程碑：

1. v0.6 安全发布与应用内更新；
2. v0.7 端到端加密同步与多设备冲突处理；
3. v0.8 经用户授权的远程内容源与发布者签名。

最终版本号为 `0.8.0`。浏览器版保留全部阅读和本地题库能力；桌面版额外提供 Tauri 签名更新。同步和远程内容源均为显式启用，不在后台自动上传数据或拉取第三方内容。

## 方案选择

### 采用：本地优先的开放协议

- 更新使用 Tauri 官方 updater、GitHub Releases 静态 `latest.json` 和不可关闭的更新包签名校验。
- 同步使用客户端 AES-GCM 加密保险库，同时支持手动文件和用户自备 REST 端点。
- 内容分发使用签名目录、可信发布者指纹和现有内容包校验器。

此方案在没有商业云服务和证书的情况下仍可完整自测、局域网使用和自行部署；未来接入正式云服务时不用改写数据协议。

### 未采用：自建账号云平台

自建注册、登录、邮件、密码恢复、数据库、账单和运维会让三个里程碑变成独立 SaaS 项目，并在没有运营基础设施时制造不可兑现的安全承诺。

### 未采用：绑定单一第三方云

直接绑定 Supabase、Firebase 或网盘 OAuth 可以更快上线远程存储，但会引入部署密钥、平台锁定和隐私政策依赖，不符合当前仓库的本地优先边界。

## v0.6 安全发布与更新

### 更新链路

- Tauri 桌面端注册 `updater` 与 `process` 官方插件。
- `tauri.conf.json` 固定 GitHub Releases 的 `latest.json` 端点和项目 updater 公钥。
- 发布构建启用 `createUpdaterArtifacts`，由 `TAURI_SIGNING_PRIVATE_KEY` 生成 `.sig`；私钥永不进入仓库。
- 普通 `desktop:build` 继续生成无需私钥的 NSIS 安装器；`desktop:release` 才生成 updater 产物。
- 更新中心允许手动检查、展示版本/说明/发布日期、显示下载进度，并在安装前二次确认。
- 浏览器环境展示“仅桌面版支持应用内更新”，不动态导入或调用 Tauri API。

### Windows 代码签名边界

GitHub Actions 提供 Authenticode 证书导入和签名配置入口。仓库无法自行签发受 Windows 信任的商业证书，因此交付内容是可验证的签名流水线，而不是伪造“已受信任发布者”的二进制。没有配置证书 secrets 时仍可构建 updater 签名的安装包，但 SmartScreen 可能显示未知发布者。

### 错误处理

网络不可用、无新版本、签名无效、下载失败和非桌面环境分别呈现明确状态。更新失败不修改本地练习数据；Windows 安装更新前依靠 Tauri 的正常退出流程。

## v0.7 端到端加密同步

### 保险库格式

`EncryptedVaultEnvelope` 使用版本化 JSON：

- PBKDF2-HMAC-SHA-256 从用户口令派生 256 位密钥；生产迭代次数固定为 310,000；
- 每个保险库使用独立 16 字节 salt 和 12 字节 IV；
- AES-256-GCM 加密，AAD 绑定 `profileId` 与协议版本；
- 明文载荷包含 v4 本地备份、来源设备 ID 和导出时间；
- 口令、派生密钥和远端 bearer token 不持久化。

手动导出生成 `.ieltsvault`，手动导入必须先解密、校验协议和预览合并摘要，再写入本地仓库。

### v4 本地状态与冲突

v3 数据自动迁移到 v4。v4 为可同步实体维护逻辑时钟和删除墓碑：

- 草稿、批注、作者草稿、偏好、收藏、掌握状态和安装包均按实体键比较更新时间；
- 成绩记录不可变，按 ID 并集合并；
- 同一实体选择较新的版本；删除墓碑比旧实体新时保持删除；
- 时间相同时使用稳定的规范 JSON 字符串比较，保证两端得出相同结果；
- 合并前展示本地/远端/合并后的成绩、草稿、批注和题库数量。

### 远程协议

同步中心保存非敏感的 profile ID、设备名和端点 URL。用户每次会话输入口令与 token。协议为：

- `GET /v1/vaults/:profileId` 返回加密 envelope 和 `ETag`，不存在返回 404；
- `PUT /v1/vaults/:profileId` 使用 `If-Match`，成功返回新 `ETag`；
- 412 表示并发冲突，客户端重新拉取、解密、合并并最多重试一次；
- 正式远端只允许 HTTPS；`http://127.0.0.1` 与 `http://localhost` 用于本地测试。

仓库提供仅保存密文的 Node 参考服务器，默认绑定 `127.0.0.1`，token 由环境变量提供。它不是托管账号服务，也不读取练习数据。

## v0.8 签名远程内容源

### 信任模型

远程目录采用 `SignedContentCatalogV1`：目录包含发布者 ID、名称、主页、公钥 JWK、生成时间和内容包清单。签名算法为 Web Crypto 支持的 ECDSA P-256 / SHA-256，签名覆盖除 `signature` 外的规范 JSON。

发布者指纹是规范公钥 JWK 的 SHA-256。第一次添加来源时，应用完成格式和签名验证后展示指纹；只有用户明确点击“信任发布者”才保存公钥。后续出现以下任一情况均阻止安装：

- 目录签名无效；
- 同一发布者 ID 更换公钥；
- 内容包下载后的 SHA-256 与目录不一致；
- 内容包自身字段校验失败、来源声明缺失或与内置题库冲突；
- URL 不是 HTTPS，也不是本地测试地址。

已信任发布者可被撤销；撤销不会删除历史成绩，但会阻止继续刷新和安装。来源订阅与信任决定保持在设备本地，不进入同步保险库。

### 内容中心

内容中心支持：

- 添加、刷新、禁用和移除目录；
- 查看发布者指纹、目录签名状态、更新时间和包数量；
- 按已安装、可安装、可升级筛选包；
- 下载后再次展示许可、来源、摘要和变更说明，再复用现有安装流程；
- 没有内置第三方题库和默认远程订阅。

仓库同时提供发布者 CLI：生成 P-256 密钥、为目录签名和验证目录。私钥文件默认被 `.gitignore` 排除；示例目录只包含公开测试公钥、原创样例内容和有效签名。

## 界面与导航

保持现有编辑部式、低噪声视觉系统。主导航继续服务练习任务；新增的系统能力归入右侧工具区：

- “同步”进入加密同步中心；
- “内容源”进入签名目录中心；
- “更新”进入桌面发布状态页。

三个页面使用一致的安全状态条、指纹块、步骤编号和审计日志，不使用夸张安全图标或伪终端装饰。移动端改为纵向步骤，所有输入、按钮和状态均可键盘访问，并遵守减少动态效果设置。

## 安全边界

- 应用不上传明文备份、口令、派生密钥、远端 token 或发布者私钥。
- 远程内容只作为 JSON 数据解析，不执行脚本、HTML 或插件代码。
- CSP 仅开放 updater 所需 GitHub 地址以及用户主动请求的同步/内容源网络访问；Tauri 权限保持最小化。
- 加密同步降低存储提供方读取数据的风险，但不能防止设备被入侵、弱口令或恶意客户端。
- 发布者签名证明“内容由持有该私钥者发布且未被修改”，不自动证明内容准确、合法或获得 IELTS 官方授权。

## 验证标准

- 单元测试覆盖加密往返、错误口令、篡改检测、v3→v4 迁移、确定性冲突合并、墓碑、目录规范化、指纹、签名与摘要失败。
- 组件测试覆盖更新中心的桌面/浏览器状态、同步预览与内容源信任流程。
- E2E 覆盖手动加密保险库往返、并发同步合并、添加签名样例目录和安装远程包。
- `npm run check`、Playwright 桌面与移动项目、`cargo check` 和 Windows NSIS 构建全部通过。
- 发布包包含 updater `.sig`；普通安装器和 updater 产物的 SHA-256 均记录在交付结果中。

## 明确不在 v0.8 内

- 托管账号注册、密码找回、付费、社交登录和云服务 SLA；
- 自动信任目录、后台静默安装内容或绕过用户确认；
- 商业 Authenticode 证书采购；
- 词汇 SRS、听力、写作和口语评分，它们保留给后续里程碑。
