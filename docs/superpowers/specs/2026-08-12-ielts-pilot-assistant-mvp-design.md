# IELTS Pilot AI 助手 MVP 设计

## 目标

在现有 IELTS Pilot 阅读、错题与写作工作台中加入一个按需出现的学习助手。助手读取用户明确授权的本地学习统计，回答“当前进度、主要问题、提高方向”等问题。入口为右下角悬浮球，点击后打开悬浮对话框，不占用现有页面宽度。

## 已确认的产品边界

- 助手名称与产品名称统一为“IELTS Pilot”。
- MVP 为只读学习教练，不自动修改练习、错题或计划。
- 正式练习和模考页面隐藏悬浮球，结果页及其他页面正常显示。
- AI 仅在用户点击快捷问题或主动发送消息时调用，不做后台轮询。
- 本地规则负责计算事实，AI 负责解释、归纳和提出建议。
- 关键诊断附带 1 至 3 个轻量证据标签，不建设复杂证据链。
- 样本不足时明确显示“数据不足”，不生成确定性结论。

## 设计方向

Reading this as: 现有学习工作台的增量功能，面向需要专注阅读与复盘的 IELTS 学习者，延续克制、编辑感和本地优先的界面语言。

- `DESIGN_VARIANCE: 4`：遵循现有网格与清晰信息层级。
- `MOTION_INTENSITY: 3`：仅为打开、关闭、发送和状态变化提供反馈。
- `VISUAL_DENSITY: 6`：在有限悬浮空间内呈现诊断和证据，但保持可扫描性。
- 保留现有纸张色、蓝色信号色、直角表面和中性阴影体系，不引入新的 UI 框架或图标依赖。

## 用户体验

### 悬浮球

- 固定于桌面右下角，具备至少 52×52 像素点击区域。
- 显示“IP”字标和可访问名称“打开 IELTS Pilot”。
- AI 未配置时显示小型空心状态标记；可用时显示实心状态标记。
- 点击后打开对话框；按 Escape、点击关闭按钮或再次点击悬浮球可关闭。

### 对话框

- 桌面端为右下角悬浮面板，最大宽度 440 像素、最大高度受视口限制。
- 小屏设备切换为底部面板，并避开现有底部导航。
- 首屏展示三个本地诊断：当前状态、主要问题、提高方向。
- 每项诊断附带轻量证据标签，例如“近 3 次”“平均 Band 6.5”“共 18 题”。
- 提供三个快捷问题以及自由输入框。
- AI 回复以流式加载状态和纯文本显示；本地会话只保存消息，不保存密钥。
- AI 不可用时，本地诊断仍可查看，并提供前往设置的入口。

### 设置

- 新增 AI 助手设置区，包括 Endpoint、Model、API Key、测试连接、保存和清除密钥。
- Windows 桌面端将 API Key 通过当前用户作用域的 DPAPI 加密后写入应用数据目录；Endpoint 和 Model 作为非敏感设置保存在现有本地设置存储中。
- 浏览器生产网关继续从启动配置文件读取密钥，前端只显示连接状态和模型，不接收或回显密钥。
- 保存后立即清空表单中的密钥值，日志、备份、对话和截图均不得包含密钥。

## 数据与架构

### 本地学习快照

`LearningSnapshot` 由现有阅读记录、错题掌握状态和写作报告构建，包含：

- 练习次数、平均与最佳 Band、累计专注分钟；
- 最近五次表现与趋势；
- 各题型正确率和样本数；
- 未掌握错题数；
- 写作报告数量和最近一次辅助 Band。

`buildCoachOverview` 从快照生成三个确定性诊断。题型薄弱项至少需要 5 道样本，趋势至少需要 3 次练习。

### AI 通道

- Web：`/api/v1/assistant/health` 与 `/api/v1/assistant/chat`，由本地生产网关注入密钥。
- Desktop：Tauri `chat_assistant` 命令从 DPAPI 密钥库读取密钥并请求 OpenAI Chat Completions 兼容接口。
- 请求只包含结构化学习快照、最近对话和当前问题；不发送完整本地数据库。
- 系统提示要求模型区分事实与建议、引用快照中的证据、拒绝声称官方 IELTS 成绩。

## 错误处理

- 缺少配置：展示设置入口，不阻塞本地诊断。
- 网络、超时、限流或无效响应：在对话内显示可恢复错误并允许重试。
- 快照为空：展示首次练习指引，不向模型伪造诊断。
- 消息长度和历史条数设上限，避免超大请求。

## 验收标准

1. 安装演示数据后，悬浮球首屏显示三项带证据的诊断。
2. 未安装数据时明确提示样本不足。
3. 模考和专项练习进行中不显示悬浮球。
4. 设置页能够显示 AI 状态；桌面端可保存、测试和清除安全密钥。
5. 使用指定本地配置启动生产网关后，可以完成一次真实 AI 对话。
6. API Key 不出现在浏览器存储、应用日志、Git 差异和截图中。
7. 单元测试、集成测试、生产构建和 Rust 检查通过。

## 自查结论

设计没有待定项；范围限定为单会话、只读诊断与 OpenAI 兼容接口。多 Provider、计划写入、后台周报和主动提醒不属于本次 MVP。
